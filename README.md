# Арбитраж-сканер — бэкенд

Бэкенд приложения для просмотра **арбитражных расхождений** на криптовалютных
биржах: FastAPI + [ccxt](https://github.com/ccxt/ccxt). Кэширует сырые рыночные
данные бирж, считает выборку под каждого клиента и пушит её по WebSocket.

Фронтенд живёт в отдельном репозитории: **[arbitr-f](https://github.com/assetaskar/arbitr-f)**
(React + Vite).

- **Данные:** публичные API бирж через ccxt — только чтение, API-ключи не нужны.
- **Типы арбитража:** межбиржевой спот, межбиржевой фьючерс, базис спот↔фьючерс
  внутри биржи, funding-спред по перпетуалам.

## Запуск

```bash
./run.sh
```

Скрипт создаёт venv, ставит зависимости и поднимает сервер на
http://localhost:8000 с автоперезагрузкой. Документация API — http://localhost:8000/docs.

Вручную:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

## Запуск всего стека в Docker

`docker-compose.yml` поднимает бэкенд и фронтенд вместе. Фронтенд собирается из
соседнего каталога — по умолчанию `../arbitr-f`:

```bash
git clone https://github.com/assetaskar/arbitr-f.git ../arbitr-f
docker compose up --build
```

- Фронтенд: http://localhost:5173 (nginx раздаёт статику и проксирует `/api` и `/ws`).
- Бэкенд / документация API: http://localhost:8000/docs.

Если фронтенд лежит в другом месте, укажите путь явно:

```bash
FRONTEND_PATH=../frontend docker compose up --build
```

Только бэкенд:

```bash
docker build -t arbitr-backend .
docker run -p 8000:8000 -v arbitr-data:/data arbitr-backend
```

## Как это работает

1. Клиент (вкладка браузера) присылает свои настройки в WebSocket `/ws`: биржи,
   режим пар, котировки, исключения, пороги и интервал.
2. Бэкенд держит **общий кэш сырых данных** бирж (тикеры спота и перпов, ставки
   funding) с TTL 30 сек. Запросы чаще TTL обслуживаются из памяти, поэтому
   несколько клиентов не создают лишней нагрузки на биржи.
3. Из кэшированных тикеров строится вселенная пар: пары нужных котировок,
   **ликвидные минимум на 2 биржах** (порог «мин. объём»), минус исключения.
4. Считаются четыре типа расхождений и уходят клиенту по его интервалу.

**Периодического фонового сканирования нет** — бэкенд ходит на биржи только по
запросу клиента. Заметные расхождения пишутся в SQLite (`opportunity_history`) —
задел под графики и телеграм-алерты; вместе с алертами вернётся и фоновый цикл.

## Эндпоинты

| Метод | Путь               | Назначение                                              |
|-------|--------------------|---------------------------------------------------------|
| GET   | `/api/exchanges`   | Список поддерживаемых бирж (spot / funding)             |
| GET   | `/api/settings`    | Настройки по умолчанию для нового клиента               |
| POST  | `/api/scan`        | Разовый расчёт по переданным настройкам (без WebSocket) |
| GET   | `/api/health`      | Проверка живости                                         |
| WS    | `/ws`              | Сессия клиента: он шлёт настройки, получает свои снимки |

Настройки **не хранятся на сервере** — они принадлежат браузеру клиента
(`localStorage`) и приходят в запросе. Поля — см. `Settings` в
[app/models.py](app/models.py).

## Переменные окружения

| Переменная          | По умолчанию      | Назначение                                  |
|---------------------|-------------------|---------------------------------------------|
| `ARBITR_SETTINGS`   | `settings.json`   | Файл с дефолтными настройками (необязателен) |
| `ARBITR_DB`         | `arbitr.db`       | SQLite: кэш для тёплого старта + история     |
| `ARBITR_CACHE_TTL`  | `30`              | TTL кэша рыночных данных, сек                |

## Структура

```
app/
├── main.py              FastAPI: REST + WebSocket-сессии клиентов
├── cache.py             Кэш сырых данных бирж (TTL, stale-while-revalidate)
├── arbitrage.py         Вселенная пар и расчёт четырёх типов расхождений
├── storage.py           SQLite: тёплый старт и история расхождений
├── exchange_manager.py  Кэш ccxt-инстансов (spot/swap), список бирж
├── config.py            Настройки по умолчанию
└── models.py            Pydantic-модели
```

## Замечания

- Используются только **публичные** эндпоинты бирж — API-ключи не нужны.
- Часть бирж (напр. Binance) может быть недоступна из некоторых регионов — такие
  ошибки попадают в поле `errors` снимка и не мешают остальным биржам.
- Одинаковый тикер может означать разные монеты на разных биржах. От такого мусора
  защищают фильтр по объёму и потолок спреда (60%); при необходимости добавляйте
  пары или монеты в список исключений.
- Funding APR — грубая годовая оценка (ставка × 3 × 365), реальный интервал
  финансирования у бирж различается.
- Приложение только показывает данные и **не является инвестиционной рекомендацией**.
